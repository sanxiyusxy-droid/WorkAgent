# Code Agent v1.6 architecture

v1.6 closes the reflection feedback loop across local sessions. The runtime
can now summarize already-journaled `reflection.recorded` /
`reflection.evaluated` pairs into a frozen, deterministic outcome profile and
use that profile to calibrate how long a comparable recommendation is
observed. No model call, network service, vector database or telemetry is
involved.

> v1.8 clarification: changing the observation window can indirectly move the
> later deterministic repair/replan reaction by one tool call. It never
> directly rewrites the current action or bypasses a hard gate. v1.8 also
> closes this document's restart-provenance boundary with a durable selection
> fact and V4 snapshot.

## 1. Pipeline

```text
valid historical journals from the same workspace
  -> pair reflection.recorded with reflection.evaluated
  -> group by reflection trigger + Supervisor action
  -> deterministic counts and a Laplace-smoothed descriptive rate
  -> minimum-sample gate
  -> frozen profile injected into AgentEngine
  -> calibrate only evaluateAfterToolCalls (1..20) and prompt explanation
```

The profile is loaded once by `createRuntime`. Filesystem iteration and sample
order cannot affect it: session IDs, samples and entries are sorted before the
profile hash is calculated. Before the stable session-ID cap is applied, the
scanner reads only each candidate's first envelope timestamp. A new session
freezes a boot-time cutoff; a resumed session reuses its first valid envelope
timestamp. Sessions created after that cutoff therefore cannot enter or crowd
out that session's bounded historical candidate set.

## 2. History trust boundary

Only journals under the current workspace's `.agent/sessions` directory are
considered. The loader excludes:

- the current session;
- journals that fail sequence/checksum validation;
- journals that fail a strict replay through the production reducer;
- linked/out-of-workspace journal paths and journals larger than 16 MiB;
- degraded recovery branches;
- reflections without a machine-readable decision;
- evaluations without a matching reflection fact.

Unreadable history is advisory data and is ignored. It never blocks the
current run or changes a safety decision.

A `run.terminated` fact is not required: a strictly replayable journal may
contribute reflection/evaluation pairs that were already durably closed before
an interruption. Concurrent sessions can append additional pairs after a new
runtime has frozen its profile; those additions are visible only to a later
runtime whose cutoff admits them.

## 3. Calibration contract

The aggregation key is `(reflection trigger, Supervisor action)`. An entry
records sample/effective/ineffective counts and a Laplace-smoothed descriptive
effectiveness rate. Defaults are:

- enabled: `true`;
- minimum comparable samples: `3`;
- maximum accepted sample-bearing historical sessions: `50` (directory
  discovery itself remains O(number of session directories)).

No adjustment occurs below the sample threshold. At or above the threshold,
a smoothed rate of at least `0.75` adds one call to the configured observation
window, a rate at or below `0.40` removes one, and the middle band keeps the
configured value. The result stays within the existing `1..20` runtime bound.

## 4. Non-negotiable policy precedence

Historical outcomes do not directly rewrite the current `SupervisorAction`,
target task/step or success signals. Their bounded window can affect when a
later ineffective result becomes visible to deterministic repair policy. They
cannot override:

- plan approval and write locks;
- scope-drift or replan policy;
- permissions and tool contracts;
- Evidence freshness and Completion Gate;
- verifier verdicts;
- model/tool/turn/time budgets.

The profile is local descriptive history, not a learned reward model and not a
claim that past effectiveness predicts future correctness.

## 5. Configuration

```json
{
  "intelligence": {
    "outcomeCalibrationEnabled": true,
    "outcomeCalibrationMinSamples": 3,
    "outcomeCalibrationMaxSessions": 50
  }
}
```

Layer precedence remains managed, CLI, project, user and defaults. Bounds are
applied again inside the calibrator so direct runtime construction cannot
bypass them.

## 6. Verification

Required regression coverage includes:

- deterministic profile/hash regardless of sample order;
- minimum-sample fallback;
- smoothed counts and bounded ±1 window adjustment;
- no change to the typed Supervisor action;
- exclusion of current, degraded and invalid sessions and unpaired facts;
- prompt projection without granting authority to history;
- existing snapshot/replay, Agent evaluation, RAG evaluation and package
  gates remain green.

## 7. Remaining boundary

The profile is recomputed when a new runtime is created and then frozen for
that runtime instance. It does not share data across workspaces or users and
does not infer causal policy quality. A future version may persist an explicit
profile fact if cross-process provenance must become part of replay; that
would require a snapshot/schema migration and dedicated recovery scenarios.
Deleting or corrupting historical journals can still change a later restart's
recomputed profile because the profile itself is deliberately not journaled.
This was the v1.6 boundary; v1.8 closes it for new/updated sessions by pinning
the complete profile and provenance in `outcome.calibration.selected` and V4.
